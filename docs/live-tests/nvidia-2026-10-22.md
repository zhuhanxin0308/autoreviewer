## 结果质量与去重观察

独立复核确认 Nemotron 报告的两处根因与样例一致，安全参数化 SQL 对照未被误报。不过，其 SQL 证据片段省略了结尾的单引号，不是逐字准确的源码引用；调用流程说明也较简略。发现校验会检查结构、文件和行号，并不证明证据引文完全准确，使用者仍需对照源码。

将两次成功运行的发现集合离线比较并交给现有去重函数后，两个根因留下了三条记录：路径遍历的标题一致，合并为一条；SQL 注入标题中的 `via` 与 `in` 用词不同，保守指纹将其保留为两条。这个结果体现了当前按文件、行号、CWE 和规范化标题去重的限制，不能将记录数直接等同于独立漏洞数。

上述去重检查只是对不同扫描中的成功模型结果做离线比较，没有生成或声称存在所有模型均成功的并行审计记录，也没有掩盖此前失败。

## 探测与审计的区别

HTTP 响应只能验证特定接口请求的可达性或服务响应。工具调用探测可以进一步检查模型是否返回符合预期的工具调用结构，但仍不证明它能持续读取代码、完成审计并输出可校验的结果。模型出现在目录中同样不保证当前账户可调用。

本记录只有“已完成的模型运行”中列出的模型结果被计为完整模型审计通过；接口和工具调用探测不计入这一结果。模型完成与整个并行批次完成是不同状态。

## 使用方式与适用范围

配置见 [examples/nvidia.toml](../../examples/nvidia.toml)。示例仅记录密钥环境变量名 `NVIDIA_API_KEY`，不包含密钥；设置环境变量并安装 OpenCode 后可对自己的授权代码运行：

```bash
autoreviewer doctor --config examples/nvidia.toml
autoreviewer scan ./your-project --config examples/nvidia.toml --output ./nvidia-audit-result
```

这些是小样例的集成测试，包含部分成功的并行批次和单模型重试，不是性能、检出率或稳定性基准，不能外推到大型仓库、更多漏洞类别或其他 CLI。耗时会受模型服务负载、网络和输入规模影响。Codex CLI、Claude Code 和 Gemini CLI 的真实模型审计仍未验证；本次也没有验证平台的免费额度、计费规则或长期可用性。
